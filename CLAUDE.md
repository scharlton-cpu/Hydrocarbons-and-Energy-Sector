# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-file static HTML dashboard: `index.html`. It presents 90 Sterling Road Inc's "Hydrocarbons & Energy Program" — an executive-facing overview of a multi-billion-CFA energy investment program broken into four sectors (Exploration & Upstream, Refining, Strategic Storage, Logistics).

There is no build system, package manager, server, or test suite. The entire application — markup, styles, and logic — lives in `index.html` and runs by opening the file in a browser (or serving it statically).

## Development workflow

- **Run/preview**: open `index.html` directly in a browser, or serve the directory with any static file server (e.g. `python3 -m http.server`) and visit it. There is no dev server, bundler, or hot-reload step.
- **No install step**: dependencies are pulled from CDNs at runtime — Tailwind CSS (`cdn.tailwindcss.com`) and Google Fonts (Inter, JetBrains Mono). There is no `package.json`.
- **No lint/test/build commands exist** in this repo. Verify changes by loading the page in a browser and checking the console/UI manually.
- Edits are made directly to `index.html`; there are no other source files to keep in sync.

## Architecture

Everything is organized around a single in-memory data object and two render functions that swap the contents of one container element.

- **`PROGRAM`** (in the `<script>` block): the single source of truth for all content. It holds top-line totals (`totalCFA_m`, `totalUSD_m`) and a `components` array, one entry per sector (`upstream`, `refining`, `storage`, `logistics`), each with `title`, `cfa_m`, `icon`, `hero_img`, `jobs`, `timeline`, `details`, `economic`, and `socioeconomic` fields. To change program figures or add/remove a sector, edit this object — the UI (sidebar nav, portfolio cards, per-sector views) is derived entirely from it.
- **`viewExec()`**: renders the executive summary — hero banner with totals, strategic/economic highlight cards, and a portfolio allocation grid generated by mapping over `PROGRAM.components`.
- **`viewComponent(key)`**: renders the detail view for a single sector, looked up from `PROGRAM.components` by `key`.
- **`setTab(id)`**: the client-side "router." It fades out the `#view` container, swaps its `innerHTML` with either `viewExec()` (id `"exec"`) or `viewComponent(id)`, fades back in, and updates the active sidebar link. There is no URL routing — navigation state lives only in the DOM.
- Sidebar links call `setTab('<key>')` via inline `onclick` handlers; there's no event delegation or framework involved.
- Mobile nav toggling is handled by a plain `menuBtn` click listener that toggles Tailwind utility classes (`hidden`, `fixed`, `inset-0`) on the sidebar.
- Styling is a mix of Tailwind utility classes (loaded via CDN) and a `<style>` block defining CSS custom properties (`--ink`, `--navy`, `--accent`, etc.) plus bespoke component classes (`.card`, `.hero`, `.glass-sidebar`, `.metric`, `.kicker`, `.sidebar-link`) used for the dark navy/teal executive-report visual theme.
- Images (logo, favicon) are inlined as base64 `data:` URIs directly in the HTML; sector hero images are hotlinked from Unsplash via `hero_img` URLs in `PROGRAM`.

## Conventions to preserve

- Keep all data-driven content in the `PROGRAM` object rather than hardcoding sector text into template strings — the render functions assume this shape.
- The file previously included Gemini API integration and AI-assessment features (see the `CHANGE LOG` comment at the top of `index.html`); these were deliberately removed. Don't reintroduce external AI API calls unless explicitly asked.
- Keep the app framework-free and dependency-free beyond the existing Tailwind/Google Fonts CDN links — there's no build step to support a package-based dependency.
